# x402 Payment Contracts

> The on-chain settlement and access-gating contracts for the x402 HTTP-402
> payment protocol on Citrate. Reference for contracted integrators building
> pay-per-request APIs and agentic commerce flows.

## Overview

x402 lets a client pay for an HTTP resource by signing an EIP-3009
authorization over Wrapped SALT (`wSALT`) instead of pre-approving an allowance.
Two contracts:

| Contract | Tier | Role |
|---|---|---|
| `X402Facilitator` | commercial | Settles signed payments (single + batch), takes a fee |
| `X402Paywall` | commercial | Reference paywall: verify payment, grant time-bound access |

> **Status: pre-audit.** Both carry inline remediation notes (`SOL-01`,
> `SOL-12`) but have not completed a final third-party audit. Addresses are not
> yet listed.

## Reference

### X402Facilitator
`contracts/src/X402Facilitator.sol`, inherits `AccessControl` + `ReentrancyGuard`.
Constructor `(wSALT, treasury, feeBps)`; `feeBps` capped at 1000 (10%). Role
`FACILITATOR_ROLE` (keccak of `"FACILITATOR_ROLE"`) plus `DEFAULT_ADMIN_ROLE`.

Functions:
- `settlePayment(from, to, value, validAfter, validBefore, nonce, v, r, s)`, `nonReentrant`, `onlyRole(FACILITATOR_ROLE)`. Consumes **one** signed EIP-3009
  authorization via `wSALT.transferWithFeeAuthorization` for the gross `value`,
  splitting net + fee internally (SOL-01 fix, no separate ERC-20 approval, the
  gasless-UX claim holds).
- `batchSettle(PaymentAuthorization[] payments)`, `nonReentrant`,
  `onlyRole(FACILITATOR_ROLE)`. Same settlement per entry; emits one
  `BatchSettled` summary.
- `setFacilitatorFee(newFeeBps)`, `onlyRole(DEFAULT_ADMIN_ROLE)`, ≤ 1000.
- `setTreasury(newTreasury)`, `onlyRole(DEFAULT_ADMIN_ROLE)`.

Public state: `wSALT` (immutable), `treasury`, `feeBps`, `FACILITATOR_ROLE`.
The `PaymentAuthorization` struct is `(from, to, value, validAfter, validBefore,
nonce, v, r, s)`.

Events: `PaymentSettled(from, to, value, fee, nonce)`,
`BatchSettled(count, totalValue, totalFees)`, `FeeUpdated`, `TreasuryUpdated`.

### X402Paywall
`contracts/src/X402Paywall.sol`, reference resource gate. Constructor
`(wSALT, resourcePrice)`; deployer becomes `provider`. Access is **time-bound**
(SOL-12 fix): `accessGrantedUntil[key]` holds the expiry timestamp; `accessTTL`
(default `DEFAULT_ACCESS_TTL` = 1 day) is applied at grant time.

Functions:
- `verifyAndGrant(resourceId, from, value, validAfter, validBefore, nonce, v, r, s)`, requires `value >= resourcePrice` and current access expired; executes
  `wSALT.transferWithAuthorization(from, provider, value...)`; grants access for
  `now + accessTTL`.
- `hasAccess(payer, resourceId)`, view; true iff expiry > now.
- `setPrice(newPrice)`, `provider` only.
- `setAccessTTL(newTTL)`, `provider` only; must be > 0.

Public state: `wSALT` (immutable), `provider` (immutable), `resourcePrice`,
`accessGrantedUntil`, `accessTTL`, `DEFAULT_ACCESS_TTL`. The access key is
`keccak256(abi.encodePacked(from, resourceId))`.

Events: `AccessGranted(payer, resourceId, amount, expiresAt)`, `PriceUpdated`,
`AccessTtlUpdated`.

## Examples

```text
1. Client GET /resource  → 402 Payment Required
2. Client signs EIP-3009 transferWithAuthorization over wSALT to provider
3. Provider calls X402Paywall.verifyAndGrant(resourceId, from, value...)
4. On success, provider serves the resource; access valid for accessTTL
```

For facilitated settlement (provider collects via a facilitator that takes a fee),
the facilitator calls `X402Facilitator.settlePayment(...)` with the signed
authorization.

## Security & access

**Tier: commercial.** These contracts are the network's monetization rail; their
fee/settlement logic is implementation depth a competitor would want to clone, so
they are gated to contracted builders. The paywall is explicitly a **reference
implementation** for docs/testing, production providers should review the
time-bound access and signature-replay properties for their use case. **No
secrets here**, no keys, no private endpoints; addresses pending deployment.
